# Godot 临时导入与录制

四方向行走、静态待机、法线和金属蒙版都通过人工审查后，填写 `delivery.template.yaml`。每方向明确颜色目录、法线目录和待机帧，四方向使用同一色板和 `[128,240]` 锚点。

```sh
h3-character assemble delivery.yaml --output output/jade-traveler-v1
h3-character verify output/jade-traveler-v1
```

独立项目只交付相对路径资源包。hd-2d-godot 的私有场景不进入开源项目；以下接入发生在游戏自己的临时演示副本中。

## 临时接入

1. 记录游戏当前 HEAD、工作区改动及默认主角资源摘要。创建忽略的独立演示副本，复制当前场景、脚本、shader 和必要资源，排除 `.git`、`.godot`、历史构建包与录制结果。若有本地游戏改动，演示副本使用实际当前字节，不把仅含 HEAD 的副本冒充当前工程。
2. 将资源包的 `character/` 复制到演示副本 `assets/characters/jade-traveler/v1/`，`normals/` 复制到 `assets/character-normals/jade-traveler/v1/`。
3. 仅在演示副本修改 `scripts/character_animation.gd` 的角色 ROOT、`scripts/pixel_actor.gd` 的初始 atlas，以及 `scripts/ancient_canal/actor.gd` 的 NORMAL_ROOT。暂时替换演示主角，不覆盖正式银饰少女文件或历史证据。
4. 核对所有贴图导入参数。运行时三种图使用同一朝向、帧索引和 atlas_region。脚底仍是世界位置原点，不移动碰撞体来修正角色贴图。
5. 运行项目适用的来源、角色合同和解析检查；既有测试若写死银饰少女 108 帧或旧路径，保留原测试，用临时角色的清单生成专用校验，不伪称全套旧验收通过。

本项目提供 `examples/stage_godot_demo.py`。它只接受已放置 `demo-source.json` 来源记录且不含 `.git` 的临时副本，要求原角色路径可识别并拒绝覆盖已经导入的角色。完整可编辑法线留在资源包；游戏只导入配对运行时图集。

```sh
python examples/stage_godot_demo.py output/jade-traveler-v1 --project .local/hd2d-demo
```

慢步必须同步减慢动画，不能只降低 scripted_direction。接入工具将动画时钟改为 `delta × 实际水平速度 / 参考步速`，默认参考1.35米/秒是本次初始制作选择，可用 `--stride-reference-speed` 调整。实际速度包括碰撞后的位移速度；停止时仍保持明确待机帧。参考步速最终应对照脚触地和位移复核，避免滑步。

初次 Godot 导入后，检查新 PNG 的 `.import`，设 `compress/mode=0`、`detect_3d/compress_to=0`、`mipmaps/generate=false`，再导入一次。法线图不是 sRGB 颜色，shader 的 normal／mask sampler 不声明 `source_color`。编辑器配置及缓存放在副本 build 的 XDG 目录，避免改动日常 Godot 用户配置。

演示副本的 `build/` 放置 `.gdignore`，防止编辑器把数千张采集原帧当成运行时纹理重新导入。Git忽略与Godot资源扫描忽略是两件不同的事；接入脚本会为生成目录写入Godot忽略标记。

动画WebP是源资源包的审阅辅助，不是游戏纹理；接入时排除 `preview.webp`，避免Godot导入器无法解码该动画格式。原WebP仍保留在资源包，运行时使用PNG帧和图集。

游戏既有扫光脚本若引用旧法线清单，在副本里改成新运行时清单，并用每方向真实帧数动态循环。颜色纹理、法线图集、金属图集、原帧路径与切片均从同一帧清单验证。图集和脚底锚点检查不应依赖银饰少女的旧PNG摘要。

## 实际画面检查

Godot 桌面实际启动江南河街场景。分别确认四方向行走、停止后的平衡待机、灯光切换、金属饰品扫光、树／建筑遮挡、桥面和岸边脚底接触。灰材质检查形体，关闭法线比较差异，关闭金属高光检查蒙版。

保留截图、工程版本、角色包摘要、实际 GPU／窗口模式和检查结论。headless、CPU 联系图和最小化离屏画面分别标明，不把它们写成用户录屏。

## 录制镜头

先保留三组原片，各镜头以 1920×1080、60 FPS 为目标，实际参数以采集验证为准：

- 四方向联系图与动画预览，直观看到独立方向和完整步态。
- 江南河街慢速探索，左右行走、桥头转向、正背面和停步。
- 夜景静止及慢走扫光，法线／灰材质／金属高光的开关对比。

录制前与用户确定操作和镜头。Godot 的确定性离线电影输出可用于展示片，但记录为离线录制，不能用它证明实时帧率。保留未剪辑视频和 FFprobe 的尺寸、帧率、时长及完整解码检查。结束后关闭演示副本，正式工程仍可运行原默认角色。

2026-10-13用户最新镜头方案取代以上早期建议：只录夜晚。流程A为中距离10秒漫游，实际移动并按水平速度缩放动画。流程B使用独立进程和原地步行预览，角色固定在夜晚暗处，保持右侧面原地慢走；关闭主光、环境光和场景灯。仅冷光、仅暖光、冷暖混合依次各扫光一轮，每轮12秒，共36秒。混合阶段两灯在同一正面椭圆路径相差半周期移动，机位固定。两个流程独立动画时钟、独立拍摄文件，不能在漫游结尾直接接续灯光计时。漫游镜头使用35度FOV、相对角色 `[0,1.65,8.4]`；灯光段为观察细节缩短至 `[0,1.65,6.4]`，焦点高度均1.05米，均在演示副本配置。三分钟分镜保持设计到导入的原结构，再分别完整加入10秒与36秒镜头。

灯光测试把角色位置和相机固定。不要用实际零位移速度驱动原地走动，否则动画会停止。使用独立预览时钟，初始播放倍率0.46875：27帧、1125毫秒的步态在每个12秒阶段完整播放五遍，三个阶段之间连续，不重置姿态。光源限定在面向镜头的正面竖直椭圆上，位置相对角色为 `[1.6*cos(phase), 1.0+0.8*sin(phase), 1.3]`。左右角约51度，始终停留在可见面；高度从0.2至1.8米变化，让头发、披肩、银饰与靴子的受光梯度先后变化。仅改变水平位置且高度固定的旧方案不够明显，已保留为失败拍摄。

单灯能量3.5、范围8米，冷色RGB `[0.65,0.82,1]`、暖色 `[1,0.80,0.60]`。避免高饱和颜色掩盖白色高光。混合阶段每灯能量1.75、相差180度的轨迹相位，总能量保持3.5。两个光源都位于镜头前方，180度是椭圆上的相位差，不是把一盏灯放到人物背后。法线强度仍为0.8、银饰响应仍为0.75，保留实际材质参数。

同姿态实际GPU对照分别关闭法线与金属，旧灯光与综合新灯光对照的角色区域平均RGB差分别提升约2.10倍与1.74倍。这确认材质响应加强，不代替最终观看审查。这是本次演示参数，需结合角色世界尺寸调整。

逐帧保存角色位置、机位、动画索引、两灯启用状态和位置，以及实际颜色／法线／金属图集绑定。核对每阶段只启用要求的光源、角色和机位无位移、侧面步态覆盖完整循环。原片保留准备时间；审阅片裁去准备段后严格保留36秒，使用FFprobe和完整解码检查帧数与时长。


## 银饰镜面反馈修订

最新银饰展示使用粗糙度0.12、金属度0.95、SPECULAR参数1.0，仅作用于原金属蒙版；布料和颜色纹理保持。灯强更新为单灯1.8、混合每灯0.9，其他位置、机位和时钟沿用前述36秒独立实验。此前3.5／1.75灯强是法线观察版本，独立保留，不作为此次镜面反馈成片。用polished_silver 0／1采集同姿态、同灯位前后对照，随后独立录制相同扫光和步态时钟。参数片段和解释见[银饰镜面高光专题](../topics/silver-specular-feedback.md)。


最新局部形体版本v7取消头发和衣物整体法线增幅，改用独立部位朝向的可编辑法线。腰饰材质参数与头顶掠光更新见银饰专题；新灯路每轮前6秒走低位正面弧线，后6秒从端点经头顶3米返回另一端。冷／暖／混合各12秒，机位仍固定。混合两灯相差半周期，各0.9能量。

材质在每次方向绑定时同时绑定response_atlas，不能把右侧图集误用于其他方向。腰饰补充函数在普通银材质赋值之后应用：

```glsl
float waist = waist_response(coord, silver);
ROUGHNESS = waist_silver_roughness(ROUGHNESS, waist);
ALBEDO = waist_silver_reflectance(ALBEDO, waist);
```

clay检查保持统一灰ALBEDO，不套用腰饰颜色混合。实际展示的源色PNG保持原样，但银材质反射率已有调整，截图说明必须如实区分。

## 边缘检查与无损录制

外部块的排查顺序为：原始 H3 帧 → 神经蒙版 → 前景 RGB 恢复 → 256 帧 → 每帧法线与金属归属 → GPU PNG → 最终视频。不要只检查调色板之后有没有洋红色。

使用 Godot `--write-movie <输出目录>/raw.png --fixed-fps 30` 输出 PNG 序列。局部放大从该 RGB 原帧制作，再统一编码。保留无损 RGB 母版和原帧；420 MP4 仅作播放副本，不能再从中取图制作放大镜头。禁止用旧 MJPEG/H264 二次放大的截图作为边缘修复验收。

## SpriteLamp 式四向观察片

另建暗底双视口，分别显示原色和灰材质；使用同一朝向、同一帧索引、同一相机和灯位。仅一盏白色点光，能量 0.7，范围 8；关闭环境光、天空反射与场景几何。角色持续右侧原地慢步，播放倍率 0.46875。

相对角色中心 `[0,1.1,0]` 的光位为上 `[0,1.6,1.3]`、下 `[0,-1.6,1.3]`、左 `[-1.6,0,1.3]`、右 `[1.6,0,1.3]`，均保持正面偏移 1.3。每向 6 秒，切换后前 0.8 秒平滑过渡，之后固定。共 24 秒、720 个有效 PNG 帧，独立于漫游及冷暖环绕。只称作 SpriteLamp 式观察，不宣称复制其全部生成器和阴影功能。

四向观察片 v10 降低的是点光强度（1.8 → 0.7），环境光原本已经为 0。关闭点光的实际 GPU 截图中角色呈黑色；勿通过压暗颜色纹理或后期曝光替代灯光调整。此参数仅用于四向白光实验，冷暖环绕仍沿用单灯 1.8／混合每灯 0.9。

切换方向时，顶部方向词与下划线、底部当前 part 中的方向词同步高亮：上方金黄 `#f5c96b`、下方蓝 `#8cbfff`、左侧青绿 `#73dfc5`、右侧珊瑚红 `#ffa18e`。“照射”和其余标题保持白色。独立 24 秒片另用四段进度条，各段 6 秒。

用户选定参数后的四向 v12：点光 2.65、环境光 0、法线 0.8、正面距离 0.8 米、左右幅度 1.7 米、上下幅度 1.6 米、范围 7.6 米。按用户明确要求，四向录像播放倍率为 1×；冷暖环绕仍是既有独立慢步实验。使用 [GPU 调参台](../../examples/video/lighting-control/README.md) 保存后，再运行 `record_saved.py --playback-scale 1`。Godot MovieWriter 在脚本初始化前固定输出大小，录像工具需先暂时设置隔离项目的 1080p 尺寸，结束恢复；必须核对每张实际 PNG 尺寸，不能仅凭命令行 `--resolution` 或窗口大小宣称 1080p。
